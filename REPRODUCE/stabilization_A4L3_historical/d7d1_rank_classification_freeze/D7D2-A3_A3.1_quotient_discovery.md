# D7D2-A3 / A3.1 — Quotient Discovery: findings so far

## A3 (v1): whole-component global fingerprint — REJECTED

Signature = root-identity partition + per-current-component shape class
(POINT / LINE_X / exact translation-normalized fingerprint), corridor
length dropped.

```text
k=6: 9,524 states / 9,524 signatures   (0% compression)
k=7: 21,963 states / 21,963 signatures (0% compression)
```

**Cause (confirmed):** the core anchor `(-4,1,0)` and satellite differ in
`y` (1 vs 2), so shortest bridges have exactly one bend, and
`certificate_bridge_actions` realizes every monotone ordering, i.e. every
bend position along the corridor. Translating the whole component to its
own min-corner keeps the bend position baked into the fingerprint (it
doesn't cancel out), so almost every state gets a distinct fingerprint.
**Conclusion: whole-component canonicalization is unsuitable, confirmed
computationally, not just in principle.**

## A3.1 (v1): single-anchor radius windows — REJECTED (real but invalid compression)

Signature = partition + raw points within radius R of `(-4,1,0)` + raw
points within radius R of `s_k` (translated) + a 3-way corridor mode
(`Y1_ONLY`/`Y2_ONLY`/`MIXED`) for whatever lies outside both windows +
connectivity flag.

```text
k=6, R=2: compression=83.2%, inconsistent 397/1260 groups (31.5%)
k=6, R=3: compression=58.8%, inconsistent 286/2465 groups (11.6%)
k=6, R=4: compression=24.9%, inconsistent 277/2276 groups (12.2%)
```

**Diagnosed cause (confirmed by direct example):** a single-point radius
window is too crude — the fixed 8-point core has sub-components more than
radius 3–4 away from that one corner point, so parts of the *actual, fixed
core* were falling outside the "core window" and getting silently folded
into the abstracted corridor bucket, corrupting the signature. Printed a
concrete pair of same-signature states with a differing raw point outside
the windows and different successor counts (13 vs 14) confirming this.
**Conclusion: radius-from-one-point windowing is unsuitable.**

## A3.1 (v2): fixed x-cutoff windows — a real bug was caught mid-session

Redesigned windows using the actual core/satellite separation axis:
`W_core` = all points with `x >= -4` (the entire fixed core, whatever its
sub-structure — no leakage by construction), `W_sat` = points with
`x <= -k+margin` (near satellite, translated by `+k`), interior = the
strict band between.

**A real bug was found and fixed before any number below was reported:**
the first implementation wrote the interior condition as
`CORE_X_CUTOFF < x < sat_x_cutoff`, i.e. `-4 < x < (-k+margin)`. Since
`-k+margin` is far more negative than `-4` for any nontrivial `k`, this
condition is vacuously false — so the "interior" band silently included
**zero points**, and any real point lying between the two windows was
dropped from the signature entirely rather than abstracted. This produced
spurious-looking "compression" (up to 47% at k=7) that was actually
**information deletion**, not quotienting. It was caught by manually
inspecting a supposedly-consistent state pair (`connected=False`,
`mode=NO_INTERIOR`, equal successor *counts* but different successor
*signature values*) — the mode should not have been `NO_INTERIOR` given
the actual geometry, which is what exposed the inverted inequality. Fixed
to `sat_x_cutoff < x < CORE_X_CUTOFF` and every number below is from the
corrected code.

### Corrected results

```text
k=6, margin=0: compression=13.5%, inconsistent 32/1118   groups (2.9%)
k=6, margin=1: compression=0.0%  (no interior band exists at this k,margin)
k=7, margin=0: compression=42.4%, inconsistent 128/3544  groups (3.6%)
k=7, margin=1: compression=8.1%,  inconsistent 3/1551    groups (0.19%)
k=8, margin=1: compression=33.1%, inconsistent 264/6914  groups (3.8%)
```

## Honest current state

- Real, bug-free compression exists (8–42% depending on margin/k), unlike
  the fully-rejected v1 attempts.
- It is **not yet a valid quotient**: inconsistent groups are non-zero at
  every margin/k combination tried so far.
- The inconsistency rate at margin=1 does **not** shrink with k — it goes
  0.19% (k=7) → 3.8% (k=8), the wrong direction for a "stabilizing"
  quotient. This is a genuine negative signal, not yet explained.
- No stabilization claim is made. `Q_k ≅ Q_{k+1}` has not been observed at
  any margin tried.

## Next candidate refinements (not yet attempted)

1. Finer corridor-mode classification: 3 buckets (`Y1_ONLY`/`Y2_ONLY`/
   `MIXED`) may still be too coarse near the window boundary — e.g.
   distinguish "bend is exactly at the window edge" from "bend is deep in
   the true middle".
2. Track *other* components' occupancy explicitly (the two-window scheme
   still lets far-away small components move around undetected inside
   whichever window they fall into) rather than assuming only two
   anchors matter.
3. Investigate the specific k=8-margin=1 inconsistent examples the way
   the k=6/R and the vacuous-interior bugs were diagnosed here, before
   trying larger k.
